## v1.8.0 更新摘要（据官方 Release Notes 概括，原文见发布页）

问题修复：
- 跟单 OSO 的止盈止损不再被误撤：同一合约两组 OSO 分开计算退出额度。官方注明此项「尚未在真实 Demo 上复现验证」。
- 主账户不开 ATM、手动挂出的反向止盈/止损不同步已修复：跟随账户成交台账按券商持仓自动校准（risk-ledger-realigned）。
- 隔夜持仓的止盈止损不同步已修复：跨交易日按实际持仓核实，以隔夜数量为上限复制。
- 连接短暂未同步、查询超时或限流时，主单不再直接记为漏单，重连后重新跟单、查询失败重试。
- 跟单引擎内部出错时不再断开连接或删除已保存的登录。
- 结果未知的下单：连续两份完整快照都确认券商未收到时，才用新请求重新跟单，不原样重发。

新功能：
- 账户本地备注名（可搜索，不影响券商名称/下单身份/跟单绑定）。
- 跟单组表成员行标出「主账户 / 跟随账户」身份。
- 新增 WinUI 3（Fluent）主题：在 data/config.json 写入 {"skin": "fluent"} 开启；Material Design 3 主题已移除。
- 笔记本高缩放适配：窗口按屏幕工作区调整、放不下整页滚动。

开发中：「手动下单」页仍在开发，默认隐藏。

官方更新方法：软件内「设置 → 关于与更新」检查更新 → 关闭软件，用新 EXE 替换旧 EXE、保留 data 文件夹（建议先备份）→ 重开后跟单组为停止状态，需手动启动。

官方隐私说明（原文概括）：除连接的交易平台、版本更新检查和用户自己开启的微信推送外，软件不向外发送数据；开启推送后，推送内容（账户名、合约、价格等）会经过并保存在 Server酱 的服务器上。

官方免责（原文概括）：复制到多个账户会同时放大盈利和亏损；网络中断、订单延迟、拒绝或部分成交、平台变化和程序缺陷都可能使跟随账户与主账户不一致，监控全部账户仍是使用者的责任。

## 风险提示（收录者独立判断，非官方说明）

1. 闭源且不可审计：仓库无源代码、无许可证，EXE 内部行为无法核查，而它要接触 Tradovate 登录与实盘/考试账户下单。信任完全建立在发布方信誉上。
2. Prop firm 合规风险：多账户复制跟单、相同身份下高度一致的成交，正是多家 prop firm（含 TPT 类规则）重点核查、可能导致拒付的行为类型。使用前应先逐家确认该 prop firm 是否允许第三方跟单软件与跨账户复制，不要默认「软件能用 = 规则允许」。
3. 本版有一项核心修复官方自述未在真实 Demo 复现验证；涉及止盈止损误撤的问题，应先在模拟/小账户验证再上真实账户。
4. 微信推送经 Server酱：开启后账户名、合约、价格会存到第三方服务器，与「不希望交易信息经企业微信形态通道留痕」的一贯偏好需自行权衡。
